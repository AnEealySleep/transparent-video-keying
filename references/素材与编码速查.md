# 素材与编码速查（ffmpeg）

> 抠像的效果上限由**素材**决定，参数调得再好也救不回一条背景不干净的视频。
> 下面是这套方案里实际用到的命令，含每条踩过的坑。

---

## 一、规格一览（先看这张表再动手）

| 项 | 要求 | 原因 |
|---|---|---|
| 容器 / 编码 | MP4 + **H.264 Baseline / Main** | ⚠️ **High profile 在部分安卓 WebView / 老 Chromium 上全黑，且不报任何错** |
| 分辨率 | 竖版 720×1280 或 1080×1920 | 桌宠是竖构图 |
| 帧率 | 24 ~ 30fps | 抠像按 30fps 节流，再高也是白解码 |
| 像素格式 | `yuv420p` | 兼容性最好 |
| 背景 | 纯黑（Y≈16~19）或纯绿（建议 `#00B140`） | 深灰会被判成半透明 → 一层灰雾 |
| 音轨 | 去掉 | 播放器反正全 `muted`，留着白占体积 |
| 人物占比 | 画面高度的 85%+ | 黑边多了，抠像后人物在窗口里会显得很小 |

---

## 二、常规处理

### 2.1 去音轨 + 压缩 + 规范编码（最常用）

```bash
ffmpeg -i in.mp4 -an \
  -c:v libx264 -profile:v main -level 4.0 -pix_fmt yuv420p \
  -crf 20 -preset medium -movflags +faststart out.mp4
```

- `-an` 去音轨；`-profile:v main` 避开安卓全黑坑；
- `-movflags +faststart` 把索引挪到文件头，浏览器可以边下边播；
- AI 生成的素材常见 **20 Mbps**（39MB / 15 秒），压到 1~3 Mbps 视觉上几乎无差。

### 2.2 裁掉两侧黑边（让人物在窗口里更大）

```bash
ffmpeg -i idle.mp4 -vf "crop=440:1280:140:0" -an \
  -c:v libx264 -crf 20 -preset medium -movflags +faststart idle_crop.mp4
```

`crop=宽:高:起始x:起始y` → 从 x=140 处裁 440 宽。人物占比 52% → 85%。

> ⚠️ **只裁横向的收益只有"窗口变窄"，人物不会变高。** 人物高度上限由屏幕高度决定，
> 而且横向裁切会让浮动 UI（气泡 / 面板）一起变窄。想让人物更大，见 SKILL.md 第 6 节。
>
> ⚠️ **偶数取整**：`crop=1080:1721:0:120` 会被 ffmpeg 取成 **1720**（H.264 要求偶数）。
> 想要精确尺寸就自己先取偶，别指望它按你写的数走。

### 2.3 乒乓循环（解决"循环跳帧"最有效的一招）

把视频**正放一遍 + 倒放一遍**拼接，循环接缝处天然连续。

```bash
ffmpeg -i in.mp4 -filter_complex \
  "[0:v]split[a][b];[b]reverse[r];[a][r]concat=n=2:v=1:a=0[out]" \
  -map "[out]" -an -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 20 -preset medium out.mp4
```

实测：首尾帧相似度 **PSNR 22dB → 38dB**（35dB 以上就算无缝）。代价是时长翻倍。

> **更好的办法是治本**：用生成工具的**首尾帧**功能，首帧和尾帧上传同一张图，
> 生成出来天然无缝，连乒乓都不用做。

### 2.4 检查素材规格（改完一定回验）

```bash
# 视频轨：编码 / profile / 分辨率 / 帧率
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,profile,width,height,r_frame_rate \
  -of default=nw=1 in.mp4

# 有没有音轨（应只有一条 video）
ffprobe -v error -show_entries stream=codec_type -of csv=p=0 in.mp4
```

★ **改完必须 ffprobe 回验**：只做文件拷贝的脚本会把不合规的素材静默放过去
（实测踩过：脚本只 `copy2`，把 High profile 原样拷进去，真机全黑才发现）。

## 三、如果你确实要 alpha 通道

### 3.1 先确认你只能做 WebM

| 格式 | 带 alpha | Chromium / Electron 能播 |
|---|---|---|
| MP4 (H.264) | ❌ | ✅ |
| MP4 (HEVC with alpha) | ✅ | ❌ |
| MOV (ProRes 4444) | ✅ | ❌ |
| **WebM (VP9 + alpha)** | ✅ | ✅ **唯一可用** |

⚠️ **剪映 / Premiere / Media Encoder 都导不出带 alpha 的视频。**

### 3.2 黑底 MP4 → 透明 WebM

```bash
ffmpeg -i 黑底.mp4 \
  -vf "lumakey=threshold=0.08:softness=0.06,format=yuva420p" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0 -b:v 3M out.webm
```

### 3.3 绿幕 MP4 → 透明 WebM

```bash
ffmpeg -i 绿幕.mp4 \
  -vf "chromakey=0x00FF00:0.15:0.05,format=yuva420p" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0 -b:v 3M out.webm
```

### 3.4 PNG 序列 → 透明 WebM

```bash
ffmpeg -framerate 24 -i frame_%04d.png \
  -c:v libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0 -b:v 3M out.webm
```

> ⚠️ **`-auto-alt-ref 0` 必须加**，否则 VP9 的 alt-ref 帧会把 alpha 通道吃掉，
> 导出的文件是**黑的**（不是"没抠干净"，是整条透明信息没了）。

## 四、造绿幕测试素材（踩坑记录）

想验证绿幕抠像算法，需要一条"内容已知"的绿幕素材。从现成的黑底素材合成：

```bash
ffmpeg -i 黑底.mp4 -f lavfi -i color=c=0x00B140:s=1080x1920:r=24 \
  -filter_complex "[0:v]colorkey=0x000000:0.06:0.02,format=yuva420p[k];\
[1:v][k]overlay=shortest=1,format=yuv420p[v]" \
  -map "[v]" -an -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 18 -preset medium 绿幕.mp4
```

### 坑 1：`maskedmerge` 的 mask 必须算在**原视频流**上

```bash
# ❌ 错：mask 从绿色源 [0:v] 算 → mask 恒为全白 → 整幅图被填成绿（人物也一起变绿）
# ✅ 对：mask 从原视频流算
-filter_complex "[1:v]format=gray,maskedmerge..."   # mask 取自原视频那一路
```

**更省事也更可靠的写法**是上面的 `colorkey 抠黑 + overlay 到绿底`，不涉及 mask 方向问题。

### 坑 2：抠黑阈值取 **12 附近**，不是 44

实测原素材：**背景噪点 0~9，人物暗部从 12 起**。阈值取 12 能干净分离；
取 44 会把人物暗部一起划给背景（实测 12~44 之间有 22340 个像素 = 1.08% 被误伤）。

## 五、其他实测坑

| 坑 | 说明 |
|---|---|
| **别用 `drawtext`** | 本机 ffmpeg 构建缺 fontconfig → **段错误（Segmentation fault）**。要加文字用别的手段 |
| **别用 `file://` 写法喂路径** | 本机这个 ffmpeg 构建**完全不吃 `file://` 前缀**（纯 ASCII 路径也报错）。直接给路径字符串 |
| 从脚本调用时注意路径 | Windows 下别在 `.bat` / `.ps1` 里硬编码中文绝对路径，用 `%~dp0` 相对定位 |
| 验证"打包是否吃到改动"，**看 md5 别看文件大小** | 4 字节对齐会把小差异吸收掉，加了 2000 字节后文件总大小可能分毫未变 |
